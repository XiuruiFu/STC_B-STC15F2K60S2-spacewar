# Spacewar! 通信协议规范 (Protocol Specification)

本文档是 Host MCU、Slave MCU、PC Renderer 三端的**唯一权威契约**。任何一端编码/解码都必须严格遵守。

> **字节序**：本协议所有多字节字段均未使用（坐标/角度/生命均为单字节），无端序问题。校验和为单字节无符号加法，溢出自然截断到低 8 位。

---

## 1. 物理层

| 链路 | 接口 | 波特率 | 方向 | 内容 |
|------|------|--------|------|------|
| Host → PC | Uart1 (Micro-USB) | 115200 | 下行 | 游戏状态帧 |
| Slave → Host | Uart2 (RS485) | 38400 | 上行 | P2 按键掩码帧 |

- 帧头均为 **2 字节**，校验和为 **1 字节**（帧内其余所有字节之和的低 8 位）。
- 接收端须校验帧头与校验和，非法帧丢弃。

---

## 2. Slave → Host 按键帧 (4 字节固定)

| 偏移 | 字段 | 值 |
|------|------|-----|
| 0 | 帧头 0 | `0xA5` |
| 1 | 帧头 1 | `0x5A` |
| 2 | 按键掩码 `keys` | 见下 |
| 3 | 校验和 | `(0xA5 + 0x5A + keys) & 0xFF` |

`keys` 位定义（1 = 按下，0 = 松开）：

| bit | 含义 | 按键 |
|-----|------|------|
| 0 | 向前推进 | Key3 |
| 1 | 向后推进 | Key1 |
| 2 | 发射/确认 | Key2 |
| 3 | 船头左转 | NavDown |
| 4 | 船头右转 | NavUp |
| 5 | 菜单上移 | NavLeft |
| 6 | 菜单下移 | NavRight |

---

## 3. Host → PC 状态帧 (可变长度, 由 BULLET_MAX 推导)

帧长 `N = 16 + 6*BULLET_MAX`（`BULLET_MAX` 为每船同时在场子弹上限，Host `config.h` 与 PC `config.py` 必须一致）。

| 偏移 | 字段 | 说明 |
|------|------|------|
| 0 | 帧头 0 | `0xAA` |
| 1 | 帧头 1 | `0x55` |
| 2 | `state` | 状态机：0=MENU，1=PLAYING，2=GAMEOVER，3=EXITED |
| 3 | `menuSel` | 菜单选中项 0~2 |
| 4 | `p1x` | Player1 X 坐标 0~255 |
| 5 | `p1y` | Player1 Y 坐标 0~255 |
| 6 | `p1ang` | Player1 朝向角 0~255 (0~360°) |
| 7 | `p1lives` | Player1 剩余生命 0~3 |
| 8 | `p2x` | Player2 X 坐标 |
| 9 | `p2y` | Player2 Y 坐标 |
| 10 | `p2ang` | Player2 朝向角 |
| 11 | `p2lives` | Player2 剩余生命 |
| 12 ~ 12+6M-1 | 子弹区 | 共 `2*BULLET_MAX` 发，每发 3 字节 `(active, x, y)`，见下 |
| 12+6M | `p1wins` | Player1 累计胜场 |
| 12+6M+1 | `p2wins` | Player2 累计胜场 |
| 12+6M+2 | `flags` | 见下 |
| 12+6M+3 | 校验和 | `sum(byte[0..N-2]) & 0xFF` |

> 其中 `M = BULLET_MAX`。子弹区 = 偏移 `12 + 6*M - 1` 为止。

子弹区布局（偏移 12 起，`2*M` 发）：

- `b[0..M-1]` 属于 **Player1**，`b[M..2M-1]` 属于 **Player2**。
- 每发子弹占 3 字节：`active`(0/1)、`x`、`y`。
- 子弹为圆形，无朝向字段；`active=0` 时坐标字段无效。
- 每船同时在场子弹上限为 `BULLET_MAX` 发，达到上限后再开火不产生新子弹。

`flags` 位定义：

| bit | 含义 |
|-----|------|
| 0 | P1 死亡特效进行中（PC 显示爆炸） |
| 1 | P2 死亡特效进行中 |
| 2 | 本局 P1 胜利（GAMEOVER 态下有效） |
| 3 | 本局 P2 胜利 |

---

## 4. 坐标与朝向约定

- **坐标系**：逻辑场为 0~255 × 0~255 的方形场域，原点 (0,0) 在左上角。
- **环绕**：坐标越界即回绕到对侧（`x += 256; x %= 256` 语义）。
- **朝向角**：0 = 朝右 (+X)，随角度增大沿**逆时针**旋转；PC 端渲染需将角度换算为弧度 `ang * 2π / 256`。
- **黑洞**：位于场域中心 `(128, 128)`，半径 `R = 12`（逻辑单位），飞船/子弹中心进入该半径即被吞。
- **飞船碰撞半径**：`r_ship = 6`，**子弹碰撞半径**：`r_bullet = 2`（用于子弹命中判定）。

## 5. 菜单结构

`menuSel` 取值：

| 值 | 栏目 |
|----|------|
| 0 | 进入游戏 (Start Game) |
| 1 | 总胜场清零 (Clear Wins) |
| 2 | 退出游戏 (Exit) |

- `enumAdcNavKeyLeft` / `enumAdcNavKeyRight` 上下移动 `menuSel`（环绕 0↔2）。
- `Key2` 确认当前项。
- 游戏结束后自动回到 MENU 态。

## 6. 胜场持久化 (DS1302 NVM)

| 地址 | 内容 |
|------|------|
| 0 | Player1 累计胜场 (0~255) |
| 1 | Player2 累计胜场 (0~255) |
| 2 | 魔数 `0x5A`（首次上电校验，非 0x5A 则清零并写入） |

> DS1302 NVM 共 31 字节（地址 0~30），其中地址 30 被系统占用，本协议仅用 0~2。读写前须先 `DS1302Init()`。
